# Benchmark history

The CI benchmark's figures over master's commits, oldest to newest: each chart is one
figure, each point a commit (hover or focus a chart for its commit, pull request, harness
version and runs; each chart's table lists every point, linked to its commit, its pull
request and the Actions runs that measured it). The benchmark itself is
described in `bench/README.md`, and each harness version's changes in
`bench/CHANGELOG.md`.

- **Lines by harness version.** A figure means the same only within a major version of
  the harness, so each major version is its own line, and a new one starts with a
  hairline (b8, b9, …). Its first point is usually the commit before its first record,
  measured again by the new harness, so a model's correction shows as a jump at one
  commit, not as a speed-up. Where a harness also computes an earlier model's figure on
  the same runs (`eta_10`, `pipeline_eta_9`, `finalise_eta_8`, …), that figure is
  dashed, in the earlier model's colour.
- **Bands** are the 95% interval of the mean over the runs of that commit.
- **Runner speed:** GitHub's runners differ by up to about 1.8× on one commit (AMD EPYC
  7763, 9V45, 9V74, and a few Intel Xeons), so a commit measured on faster runners can look faster by itself.
  "One runner CPU" shows only one CPU model's runs; "Paired change" shows each run's
  change against the commit it ran beside on the same runners, which runner mix
  cannot move.
- **Backfill:** the campaign's milestone commits from #84 to #132 (marked on the x axes),
  measured by bench 11.0.0 from the Actions tab, each paired with #132 on the same
  runners, join bench 11's line, so its figures (the measured end-to-end total among
  them) reach back past its own records. In "Paired change" they are a line against
  #132. Bench 12.0.0's line starts at #136 (a docs-only commit after #132, so #132's
  code), measured again by it as the commit before its first record.

What the recent major versions changed (each a break in the figures it names):

| version | pull request | what changed meaning |
|---|---|---|
| 12.0.0 | #133 | the pipeline's input: its chunks are the split's own output (5 chunks on the quick tier, not 4; 42 on the full tier, not 66), so every pipeline and finalise figure. The ETA model is 11.0.0's |
| 11.0.0 | #130 | the pipeline ETA (its worker starts a fixed cost), and the split's slice written as the dumps write it (the split's figures and ETA); the measured end-to-end total added |
| 10.0.0 | #128 | the pipeline and finalise ETAs: the claims scaled by their own rows and bytes, not by entities |
| 9.0.0 | #119 | the finalise ETA: worker start-up a fixed cost; finalise's peak RSS at a release added |
| 8.0.0 | #111 | finalise on three times the rows: the claims key from a release's file layout; finalise's peak RSS added |

The data is `scripts/bench_history.py`'s, from the `bench-results` branch (master's
records) and `docs/benchmarks/backfill/`, regenerated by the site's build on every push to
master and after every Benchmark run on master.
